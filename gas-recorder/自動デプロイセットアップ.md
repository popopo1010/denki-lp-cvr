# GAS自動デプロイ セットアップ（clasp + GitHub Actions）

`main` の `gas-recorder/` が変わると、GitHub Actions（`.github/workflows/deploy-gas.yml`）が
Apps Script プロジェクトへ自動反映し、**既存Webアプリデプロイを新バージョン化**する
（`/exec` のURLは変わらない）。これで「リポジトリは直っているのにGASが古い」というズレが起きなくなる
（2026-08-30 テスト送信ゲート実装時にこのズレが顕在化した）。

## 一度だけ必要な準備（オーナーのPCで）

※ **Secret `CLASPRC_JSON` が既に登録済みで、ワークフローが緑ならこの準備は不要**
（2026-08-30 時点で2ヶ月前登録のSecretが存在）。ワークフローが認証エラーで
落ちたときだけ、以下でSecretを作り直す。

1. ターミナルで clasp を入れてログインする（ワークフローはv3を使うが、
   認証ファイルは**v2/v3どちらの形式でも読める**のでバージョンは最新でよい）:

   ```bash
   npm i -g @google/clasp
   clasp login
   ```

   ブラウザが開くので、スプレッドシート「LP form recorder」のオーナーである
   Googleアカウントでログインして許可する。

2. 認証情報ファイルの中身を表示してコピーする:

   ```bash
   cat ~/.clasprc.json
   ```

   出力された `{ ... }` 全体をコピー。

3. GitHub で Secret に登録する:
   - リポジトリ `popopo1010/denki-lp-cvr` → 上部タブ **Settings**
   - 左メニュー **Secrets and variables → Actions**
   - **New repository secret**
   - Name: `CLASPRC_JSON` ／ Secret: さっきコピーした中身を貼り付け → **Add secret**

4. 動作確認（初回は手動実行）:
   - リポジトリ → **Actions** タブ → 左の **Deploy GAS (gas-recorder)** → **Run workflow**（main）
   - 緑になれば、GASエディタを開かなくても main の内容が反映されている。

## 安全装置（ワークフローに組み込み済み）

- **URLは変わらない**: 既存デプロイ（`GAS_DEPLOYMENT_ID`）の「新バージョン化」だけを行う。
  新規デプロイ作成はしない（URLが変わると全LPの `GAS_URL` が死ぬ）。
- **削除ガード**: push 前にリモートのファイル一覧を照合し、リポジトリに無いファイルが
  GAS側にあれば**中断**する（`clasp push` はリモート専用ファイルを消すため）。
- **送るファイルは `.claspignore` のホワイトリスト固定**
  （コード.js / zoho.js / agency-share.js / booking-custom.js / appsscript.json のみ）。

## 注意

- GAS側のエディタで直接コードを書き換える運用は**やめる**（次の自動デプロイで消える）。
  変更は必ずリポジトリ → main マージで反映する。
- スクリプトプロパティ（`WEBHOOK_SECRET` / `SLACK_BOT_TOKEN` 等）はコードと別管理なので
  自動デプロイの影響を受けない（消えない）。
- Secret 未登録のままワークフローが動くと、分かるエラーメッセージで失敗する（何も壊れない）。
- clasp のトークンは失効することがある。ワークフローが認証エラーで落ちたら
  手順1〜3をやり直して Secret を更新する。
