# 候補者ステージの代理店共有（個人情報なし）

マーケ代理店に「どのチャネル／キャンペーンから来た候補者が、いま Zoho CRM のどのステージか」を
**随時（1時間ごと）自動更新**で共有する。**個人情報は一切渡さない**。
コードは `gas-recorder/agency-share.js`。

## 何を共有し、何を共有しないか

| 共有する | 共有しない |
| --- | --- |
| `lead_id`（不可逆ハッシュの匿名ID） | 氏名 |
| 送信日 / 送信月 | 電話番号 |
| LP名（denkikouji / sekoukanri など） | メールアドレス |
| マーケチャネル（例 `google/cpc｜014_denki_top｜KW: 電気工事士 求人`） | 生年月日 |
| `utm_source` / `utm_medium` / `utm_campaign` / `utm_content` / `utm_term` / `utm_id` | 郵便番号・都道府県・市区町村 |
| **Zoho上の現在のステージ**（`01_新規リード` → `02_未通電` → `04_HOT` …） | 保有資格・経験・転職意欲 |
| ステージ更新日 / LINE登録の有無 | IPアドレス・UA・送信時URL（`_page`） |

- `lead_id` は「商談ID＋ソルト」のSHA-256を12桁に切ったもの。**本人には戻せない**が、
  同じ候補者は常に同じIDになるので、代理店側で重複・再訪をカウントできる。
- 広告クリックID（`gclid` / `fbclid` 等）は既定で**共有しない**。オフラインCVの取り込みで
  必要になったら `agency-share.js` の `AGENCY_SHARE_INCLUDE_CLICK_IDS` を `true` にする。
- テスト送信（連番電話番号・プレースホルダー氏名など）は自動で除外される。

## なぜ別スプレッドシートなのか

Googleの共有権限は**ファイル単位**で、同じスプレッドシート内のタブごとには分けられない。
`form_submissions` を共有すると氏名・電話まで見えてしまうため、
**個人情報を落とした行だけを別ファイルに書き出し、そのファイルだけを代理店に渡す**。

## セットアップ（初回のみ・10分）

1. `clasp push -f` でコードを反映する（`gas-recorder/` で実行）
2. Apps Script エディタで **`setupAgencyShare`** を実行
   - 共有用スプレッドシートが自動作成され、IDがスクリプトプロパティ `AGENCY_SHARE_SHEET_ID` に保存される
   - 匿名IDのソルト `AGENCY_SHARE_SALT` も自動生成される（**このソルトは変えない**。変えると
     過去の `lead_id` と繋がらなくなる）
   - 実行ログに出た共有シートのURLを控える
   - 自動作成に失敗する場合は、手でスプレッドシートを新規作成し、そのIDを
     `AGENCY_SHARE_SHEET_ID` に設定してから `syncAgencyShare` を実行する
3. **自動更新のトリガーを登録**する
   Apps Script エディタ → ⏰［トリガー］→ トリガーを追加
   - 実行する関数: `syncAgencyShare`
   - イベントのソース: 時間主導型 / 時間ベースのタイマー / **1時間おき**
   > コードからトリガーを作らないのは、`script.scriptapp` スコープの追加＝**再認可**が必要で、
   > 稼働中のフォーム受信エンドポイント（`doPost`）を止めうるため。
4. 共有シートを開き、代理店に **「閲覧者」で共有**する（編集権限は渡さない）
   - リンクを知っている全員に公開せず、**代理店の担当者アドレスを個別に指定**する
   - 「閲覧者がダウンロード・印刷・コピーできないようにする」は任意（オンでも中身は見える）

## シートの構成

| シート | 中身 |
| --- | --- |
| `候補者ステージ` | 1候補者1行の明細（1行目がヘッダー。ピボット・Looker Studio からそのまま読める） |
| `チャネル別サマリ` | 月 × `utm_source`/`utm_medium`/`utm_campaign` の 送信数・LINE登録数・ステージ別件数 |
| `凡例` | 各列の意味と最終更新時刻 |

Looker Studio で見たい場合は、この共有スプレッドシートをデータソースにする
（元の `form_submissions` は**絶対に接続しない**）。

## 運用

- **更新タイミング**：1時間ごと。毎回まるごと作り直すので、Zohoでステージを動かせば次の実行で反映される。
- **手動で今すぐ更新**：エディタで `syncAgencyShare` を実行。
- **代理店が編集しても壊れない**：次回更新で上書きされる（＝手元のメモは別ファイルに書いてもらう）。
- **Zohoが一時的に落ちている場合**：行は書き出され、ステージだけ `不明` になる。
  戻り値とSlackのエラーチャンネルに理由が出る。
- **ステージ更新日**はZohoレコードの最終更新日時。ステージ以外の項目更新でも動くため**目安**。

## ステージの見方（代理店向けの説明用）

`01_新規リード` → `02_未通電` → `04_HOT` → `09_履歴書作成` … と番号順に進む。
番号順に並べればそのままファネルになる。

- `CRM未連携` … 送信直後、またはCRM連携エラー。ステージはまだ付いていない。
- `不明` … CRM側に該当レコードが見つからない（削除・統合された等）。

## 触るときの注意

- **列を足すときは個人情報にならないかを必ず検討する**。出力列は `AGENCY_SHARE_COLUMNS` の
  許可リストだけで、書き込み直前に元データの個人情報が混ざっていないか1セルずつ検査している
  （混入を検知したら**1行も書かずに中止**する）。
- 変更したら `node scripts/check-agency-share.mjs` を実行する（`release-pre-check.sh` にも入っている）。
  GASを模したスタブ上で `syncAgencyShare()` を丸ごと1回まわし、個人情報が出ないことを検査する。
- **ソルト `AGENCY_SHARE_SALT` を変えない**（過去の `lead_id` と繋がらなくなる）。
