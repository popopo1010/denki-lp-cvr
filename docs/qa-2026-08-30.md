## 未解決課題（優先順）

1. **求人カードの本番展開は実求人データ待ち**
   参照しているのは denkikouji-trust（noindex）1本のみ、`is_sample: true`。
   `assets/data/lp-job-cards-denki.json` を実データに差し替え is_sample:false に
   するだけでLP/JSは無改修。**データの出所（シート/API/CSV）待ち**。
2. **資格別の年収相場を載せるか（オーナー検討中）**
   `nenshu-shindan/salary-data.js` に11資格分（range/avg）がある。年収診断LPで
   既に本番公開中だが、**数値の根拠が取れているかは未確認**。事実なら
   検索意図に直接答えるオリジナルコンテンツになり、下の3の類似度も下がる。
3. **工種バリアント間の類似度が約80%残っている**
   FAQ工種別化で 82.1→80.7%（建築）等まで下げたが、まだ「ほぼ同じページ」の域。
   本質的に下げるには工種ごとの本文そのものを増やす必要があり、実質 1 と 2 待ち。
4. **会社所在地・代表者が未確認**
   運営者情報ブロックの項目は 運営／許可番号／対応職種／費用 の4つ。
   確認が取れたら Organization の構造化データと表示に追加。
5. **app-v2系のエラー挙動が非統一**
   app-v2 と dk_lp/denkikouji/main.js は「未入力項目を全部列挙する」方式で
   touched を持たない。即時表示にすると1文字目から赤帯が出続けるため silent のまま。
   実測では「CTA無効なのに理由が出ない」状態は作っていないので実害はない。
   揃えるには app-v2 に touched を入れる必要があり、送信経路を触る割に得るものが
   小さい。**実機で不満が出たら着手**。
6. **sekoukanri step01 は SE(540px) で +116px はみ出しが残る**
   選択肢12個×48px(タップ下限)で幾何学的に収まらない。自動送りがあるため許容中。

## 運用の教訓

- **main→staging の順で連続pushすると main のデプロイが消える**：
  concurrency グループ（deploy-xserver）内で「待機中」のランは、後から来た
  ランに置き換えられる（GitHubの仕様。cancel-in-progress:false でも起きる）。
  e99147e / d058253 の main デプロイが2連続でこれに食われ、staging だけ
  進んで本番が古いままになった。**mainへ出すときは main を単独で先に push し、
  ランが走り出してから staging を push する**。workflow_dispatch と re-run は
  統合トークンでは 403 で使えない。
- **ローカルの `?v=` 参照は `app.js?v20260829c` 形式（`=` なし）が主流**。
  `=` 付きを仮定した一括置換は空振りする。必ず実参照を grep してから置換する。
- **自作の検証スクリプトを信じすぎない**：「無効CTAで進む」の修正を一度
  「正常入力でも詰まる」と誤判定して取り消したが、原因はテスト側だった。
  step03 の選択肢は `.js-radio-button02`（末尾02）で、`.js-radio-button` を
  押していたため選択が成立していなかった。v2 の生まれ年・dk_lp の市区町村も
  同様に埋め忘れていた。**LPごとの正しい操作を知っているのは
  `scripts/e2e-lp-flow-local.mjs` なので、フォーム挙動の可否はそちらで判定する**。
- **番人を足したら「旧コードで落ちること」を必ず確認する**：
  無効CTAの検査は2回空振りした（FVの次へが非表示でループが即終了／
  ステップ遷移が非同期なのに同期で読んでいた）。落ちることを確認して初めて番人になる。
