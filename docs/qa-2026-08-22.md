# 品質チェック結果（2026-08-22）

対象: `denki-lp-cvr` 全体（LP 60本以上 / 共有JS・CSS / 生成スクリプト / CI / リリース手順）

結論から言うと、**個々のLPの作りは良く、既存チェック（禁止コピー・クマ初期位置・参照切れ・thanks-v2）はすべて緑**だった。
問題が出たのは「LPが1本ではなく60本ある」ことに起因する場所——**直したはずの修正が一部のLPにだけ当たっていない**、
**修正を止める仕組みが本番デプロイ時にしか動いていない**、の2点に集中していた。

---

## 1. 直したもの（このブランチの変更）

### A. 再発防止の網が作業中に効いていなかった → PR/ブランチCIを新設

- 静的チェック9本は `deploy.yml`（`main`/`staging` への push）の中でしか動いておらず、
  **作業ブランチでは1本も回っていなかった**。壊れに気づくのが「mainにマージした後」だと、
  直すのに本番デプロイをもう1往復することになる。
- `.github/workflows/ci.yml` を追加。PR・作業ブランチへの push で
  **静的チェック / 生成物ドリフト / 実ブラウザE2E** の3ジョブが回る。本番・STGには一切触らない。
- `scripts/check-lp-guard.js` は手順書に載っているのにCIから漏れていたので接続した。

### B. Meta広告LPの再生成が「本番を壊すボタン」になっていた

- `本番反映手順書.md` は「元LP更新後に `python3 scripts/generate-meta-lp.py`」と案内していたが、
  **実行すると7本のMeta LPが壊れる状態**だった:
  - `meta-short-lp.css`（Meta短LP専用の `.meta-fv*` スタイル）の注入アンカーが
    `<noscript>` 依存で、2026-08-19 のCSS同期読み込み統一で `<noscript>` が消えたため**注入されない**。
  - 加えて `meta-lp/` は生成後に手で育てられており（インシデント対策CSS等）、上書きでその手当てが消える。
- 対応: 注入アンカーを現行マークアップ（`cvr-boost*.css` の同期 `<link>`）に修正し、
  **既定では既存ファイルを上書きしない**（`--force` 明示時のみ）作りに変更。手順書も書き換えた。

### C. アプリ内ブラウザ（LINE/Instagram）のバー対策が 25本のLPで抜けていた

- 「入力ステップでSTEP表示がバーの裏に隠れる」の対策
  （`html.dk-inapp ... padding-top:96px` ＋ `scroll-margin-top:120px`）が、
  **フォームを持つLP 50本のうち25本に入っていなかった**。
- そのうち **6本は Meta広告の着地ページ**（`meta-lp/sekoukanri-*`, `meta-lp-v2/sekoukanri-*`）。
  Meta広告の流入はほぼアプリ内ブラウザなので、**この対策が一番効く場所でだけ抜けていた**。
- 対応: 25本すべてに標準の2行を追加（`html.dk-inapp` スコープなので通常ブラウザには一切影響しない）。

### D. 撤去済み機能（予約カレンダー）の先読みが全LPに残っていた

- `thanks-v2` は 2026-06-23 のLINE一本化でカレンダーを撤去済み（HTML内の booking 参照は0件）なのに、
  LP側は今も `booking-slots.json`（**約54KB**）を preload+fetch し、`thanks-booking-bootstrap.js` を注入していた。
  v2系は **step06 到達時**＝入力〜送信という一番詰まってほしくない瞬間に回線を奪っていた。
- 対応: 予約カレンダーが現役の `nenshu-shindan` 系だけ先読みするようゲート。
  それ以外のLPでは 54KB + スクリプト1本が丸ごと消える。

### E. `?v=` の上げ忘れが構造的に検出できなかった

- `cvr-boost.js` は `app.js` の `?v=` を流用していたため、**cvr-boost.js だけ直しても URL が変わらず**
  古い実装が配られ続ける状態だった（「?v= を上げたのに効かない」と同型）。専用の定数に分離。
- `scripts/check-asset-versions.mjs` を新設。3つの目で見る:
  1. 同じアセットの `?v=` が全HTMLで揃っているか（**一部だけ bump** の検出）
  2. 中身が変わったのに `?v=` が据え置きでないか（台帳 `scripts/asset-versions.json` と突き合わせ）
  3. `deploy.yml` が本番で grep する期待値がリポジトリと一致しているか
     （ズレると **rsync 済み＝本番反映後**に Verify が落ちる）
- 実際にこのチェックが、作業中に作り込んだ「app.js の ?v= が7ファイルだけ古い」状態と、
  `denkikouji/steps-lazy.html` が2つのキャッシュキーで参照されていた既存のズレを検出した。

### F. 入力欄の属性がLPごとにバラバラだった（スマホの完了率に直結）

| 欠けていたもの | 対象 |
|---|---|
| 郵便番号の `autocomplete="postal-code"` | 25ファイル |
| 郵便番号の `inputmode="numeric" pattern="[0-9]*"` | 24ファイル |
| 携帯番号の `inputmode="numeric" pattern="[0-9]*"` | 54ファイル |
| 携帯番号の `minlength` が 10（他は11） | 1ファイル |

本番の主要LPには入っていて、`meta-lp` / `nenshu-shindan` / `WPLP` / `自前LP` で抜けている、という形だった。
全部揃えたうえで `scripts/check-input-attrs.mjs` で固定した。

### G. 生まれ年の受付範囲が実装ごとに違っていた

- `app.js` / `dk_lp` は **1924〜2010**、`app-v2.js` だけ **1924〜2023**。
  つまり **v2系のLPからは「2023年生まれ（3歳）」の候補者がそのまま Zoho に流れていた**。
- さらに legacy `<select>` の選択肢は両実装とも 2023 まで作られており、**自分の検証と矛盾**していた。
- 対応: 定数 `BIRTH_YEAR_MIN/MAX` に一本化し、既に本番で使われている **1924〜2010** に統一
  （HTML の `max` 33本も合わせた）。**範囲そのものは業務ルールなので下の「確認事項」を参照。**

### H. クマのタップが禁止パターン（`block:"center"`）だった

- FVのクマをタップしたときのスクロールが `scrollIntoView({block:'center'})` で、
  CLAUDE.md が名指しで禁止している「中央寄せ＝上部を押し出す」パターンそのものだった（41ファイル）。
  `block:'nearest'` に統一。

### I. Meta広告LP 6本だけ GTM が同期読み込みだった

- 他のLPは「初回インタラクション or 8秒後」の遅延ロードなのに、
  `meta-lp/sekoukanri-*` / `meta-lp-v2/sekoukanri-*` は素の同期スニペットで**FVをブロック**していた。
  他LPと同じ遅延ローダーに統一（`dataLayer` への push はキューされるので計測は落ちない）。

### K. 計測が二重に入っていた（ファネル数字が実態より多い）

- `cvr-boost.js` の `initFormTracking` が `.js-step-button` のクリックで `form_step` を push し、
  同時に `app.js` の `trackStep` が showPage で（重複排除して）同じ `form_step` を push していた。
  → **app.js系LPのステップ計測が二重計上**。しかも cvr-boost 側は「戻る」クリックも1ステップとして数えていた。
- 対応: `cvr-boost.js`（と `dk_lp` のコピー）から `initFormTracking` を削除。ステップ計測は app.js / app-v2.js を正とする。
- **残る非対称**（要判断）: `app.js` は「そのステップに到達した時」に1回、`app-v2.js` は「クリックした時」に毎回
  （戻るも含む・重複排除なし）push している。v1とv2のファネル数字を並べて比較するときは定義が違う点に注意。

### L. 存在しないファイルを毎回取りに行っていた（新設E2Eが検出）

1. `WPLP` / `自前LP` の全ページで `assets/js/cvr-boost.js` が **404**。
   app.js が無条件に注入するのに、この2ミラーだけファイルが無かった。
   しかも両者のHTMLには `.cvr-social-proof__number`（カウントアップの対象）があり、
   **動くはずの演出が動いていなかった**。ミラーにファイルを追加し、ミラー一致チェックの対象に入れた。
2. 予約枠JSONのURLがページからの相対（`"../assets/data/booking-slots.json"`）固定で、
   **深さ2のページ（`/nenshu-shindan/thanks/`・nenshu系LP）からは常に404**だった。
   静的JSONを取れずに毎回GASへ落ちていた（遅い・GAS障害時は枠が出ない）。
   自分自身の `src` から解決するよう修正し、`?v=` の無かった `thanks-booking-config/loader.js` にも版を付けた。

### N. ステップの初期非表示をテーマCSS任せにしていたLPが25本

- `.js-form-group{display:none}`（＝step01〜06を初期状態で隠す）を自前のcritical CSSに持たず、
  **本番WPテーマCSSが届くことに賭けている**LPが25本あった（Cと同じ「テンプレ取り残され」集合）。
- ローカル（テーマCSS無し）で `meta-lp-v2/sekoukanri-doboku` を開くと、
  **step01〜step06が縦に全部並んで表示された**。本番ではテーマCSSが効くので今は見えていないが、
  2026-07-08 の「テーマCSS由来でFVが消えた」インシデントと同じ依存の仕方をしている。
- 対応: `#step-first`（FV）には一切触らない書き方
  `.js-form-group:not(#step-first){display:none}` を25本のcritical CSSに追加。
  FVのレイアウトを一切宣言しないので、「FVが消える」方向の事故は起こしようがない。

## 2. 確認事項（勝手に決めない・オーナー判断）

1. **生まれ年の下限**: 1924〜2010（＝2026年時点で16歳以上）に統一した。これは既存の本番実装に合わせた結果で、
   業務ルールとして正しいかは未確認。**年が変わっても2010固定**なので、いずれ「20歳未満お断り」になる。
   「現在年 − 16」で毎年自動で動かすなら実装を変える。
2. **プライバシーポリシーのリンク先**: 171箇所が `/privacypolicy`（サイトルート＝WordPress側）を指し、
   5箇所が `/denki-lp-cvr/privacypolicy/`（このリポジトリ側）を指している。
   本環境からは外部到達がブロックされていて**実在確認ができなかった**。本番で両方の200を確認してほしい。
3. **テーマCSSの二重運用**: `denkikouji/` と `sekoukanri/`（主力2本）は `theme-snapshot.css`（同一オリジンの複製）を読み、
   他の全系統（v2 / meta-lp / nenshu-shindan / WPLP）は**本番WPテーマの `style.css` を直接**読んでいる。
   前者はテーマ変更の影響を受けない代わりに週次スナップショットPRを取り込まないとズレ、後者は即座に影響を受ける。
   どちらかに寄せる判断が要る。
4. **`meta-lp/` の位置づけ**: 現状は「生成物ではなく手編集の本番資産」。今回それに合わせて生成スクリプトを
   上書き禁止にしたが、元LPの改善（遅延GTM等）を取り込む運用は人力のまま。定期的に差分を見る運用にするか、
   生成に戻す（＝手当てを生成側へ移植する）かは要判断。

## 3. 反映手順（重要）

このブランチは **push しただけで、本番は旧版のまま**。表示に関わる変更（C・H・I）を含むので、
CLAUDE.md のルール通り **STG実機確認 → main** の順で進めること。

```bash
# 1) STGへ
git push -f origin claude/system-quality-check-i69bjb:staging
#    → https://denkilp.builders-job.com/denki-lp-cvr-stg/ をスマホ実機で確認
#       ・LINE / Instagram のアプリ内ブラウザで step04〜06 の上部が隠れないか（対策を入れた25本のうち数本）
#       ・meta-lp/sekoukanri-* のFV表示とGTM発火（Tag Assistant）
#       ・クマがCTAへ移動するか、FVのクマタップでタイトルが押し出されないか
# 2) 問題なければ main へ（本番デプロイが起動する）
```

`?v=` を今後上げたときは **`node scripts/check-asset-versions.mjs --update`** を忘れないこと。
